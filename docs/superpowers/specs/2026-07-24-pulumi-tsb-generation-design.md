# Design: generate `pulumi-tsb` from `terraform-provider-tsb`

## Context

`github.com/tetratelabs/pulumi-checkmate` is a [pulumi-terraform-bridge](https://github.com/pulumi/pulumi-terraform-bridge) provider generated from `github.com/tetratelabs/terraform-provider-checkmate`. It uses the bridge's `pf` variant (`pulumi-terraform-bridge/pf`) because `terraform-provider-checkmate` is built on `terraform-plugin-framework` rather than the legacy SDKv2.

`github.com/tetratelabs/terraform-provider-tsb` was recently rewritten from scratch against the TSB v2 gRPC API: `terraform-plugin-framework`-based, `internal/provider` layout, 47 resources generated by `cmd/gen-provider` from proto descriptors plus 1 hand-written (`access_binding`), and a private dependency on `github.com/tetrateio/tetrate`.

`github.com/tetratelabs/pulumi-tsb` already exists on GitHub but is **stale**: last pushed 2023-04-14, bridging `terraform-provider-tsb v0.0.5` (the old `pkg.NewProvider()` layout, 3 resources + 1 data source). None of its code is reusable against the rewritten provider — it needs to be regenerated from scratch, following the checkmate pattern.

This is not a one-off: `terraform-provider-tsb` will keep gaining/renaming resources over time, so the resource-mapping code in `pulumi-tsb` must be regenerated repeatedly, not hand-maintained.

## Tools used by `pulumi-checkmate` (reference pattern)

- **`pulumi-terraform-bridge/pf`** (`github.com/pulumi/pulumi-terraform-bridge/pf/tfbridge`, `.../pf/tfgen`) — the bridge for `terraform-plugin-framework` providers.
- **`pulumi-terraform-bridge/v3`** (`github.com/pulumi/pulumi-terraform-bridge/v3/pkg/tfbridge`) — `tfbridge.ProviderInfo`, `ResourceInfo`, token helpers.
- `provider/resources.go` — declares `tfbridge.ProviderInfo{P: tfpfbridge.ShimProvider(...), Resources: map[string]*tfbridge.ResourceInfo{...}, JavaScript: &tfbridge.JavaScriptInfo{...}}`, plus token-naming helpers (`checkMember`/`checkType`/`checkResourceTok`).
- `provider/cmd/pulumi-tfgen-<name>/main.go` — thin wrapper calling `tfgen.Main(name, Provider())`; produces `schema.json` and language SDKs.
- `provider/cmd/pulumi-resource-<name>/main.go` — thin wrapper calling `tfbridge.Main(ctx, name, Provider(), meta)`; the actual runtime plugin binary Pulumi shells out to, embedding `schema.json` + `bridge-metadata.json`.
- `Makefile` — chains `schema → bridge → sdk`, generates the TypeScript SDK via `sdk.nodejs`, and cross-checks version strings across `Makefile`/`go.mod`/`provider/resources.go`/`package.json`/`install-pulumi-plugin.js` (`providerversion`/`versioncheck`/`tagcheck` targets).
- `.goreleaser.yml` — builds/signs/releases the `pulumi-resource-<name>` binary; `.github/workflows/release.yml` also does `npm publish` for the TS SDK on tag push.
- `licenser` (`github.com/liamawhite/licenser`) — applies license headers, checked via `make check`.

## Decisions

1. **Repo lineage**: clone the existing (stale) `tetratelabs/pulumi-tsb` into `~/src/pulumi-tsb` first, then overwrite its content on a working branch — don't start a disconnected fresh repo.
2. **Module layout**: flat `index` module for all resources (`tsb:index/<name>:<Name>`), matching checkmate exactly — no submodule-per-TF-prefix scheme, despite tsb's resource names having prefix structure (`gateway_group`, `istio_traffic_destination_rule`, etc.). Keeps token generation unambiguous.
3. **Version pin**: `TFProviderVersion = Version = 0.1.1` (current HEAD tag of `terraform-provider-tsb` at design time), same lockstep-versioning convention as checkmate's `providerversion`/`versioncheck`/`tagcheck` Makefile targets.
4. **No data sources**: current `terraform-provider-tsb` exposes none (unlike the old stale bridge, which had a `tsb_organization` data source) — `resources.go` only needs a `Resources` map.
5. **License header**: use tsb's own convention (`header.txt` → `Copyright (c) {{ .Owner }} {{ .Year }} All Rights Reserved.`, applied via `licenser -t header.txt -m "Copyright (c) Tetrate" "Tetrate, Inc"`), not checkmate's older `Copyright 2023 Tetrate` convention.
6. **Resource-mapping code is generated, not hand-written, and the generator is kept as a permanent tool in the repo** (see below) — this is the key deviation from a literal checkmate copy, driven by the need to regenerate as `terraform-provider-tsb` evolves.
7. **Private dependency**: `terraform-provider-tsb` (and transitively `pulumi-tsb`) depends on private `github.com/tetrateio/tetrate`. Local builds rely on the existing machine-wide `GOPRIVATE=github.com/tetrateio/*,github.com/tetratelabs/*` + SSH access. CI needs the same SSH-agent + `git config url."git@github.com:".insteadOf` + `GOPRIVATE` steps that `terraform-provider-tsb`'s own `.github/workflows/go.yml` already uses — copied into `pulumi-tsb`'s `go.yml` and `release.yml` (the goreleaser build job also needs it).
8. **Nothing gets pushed automatically.** Work happens on a branch; commits are signed per the user's global git conventions; pushing is confirmed with the user first (single `origin`, no fork ambiguity here).

## The permanent resource generator (`provider/cmd/gen-resources-tsb/`)

Rather than a one-off script (or scraping `docs/resources/*.md`, which is a side artifact that can drift), this is a small Go program that:

1. Imports `terraform-provider-tsb/internal/provider`, calls `provider.New()()` to get the live `provider.Provider`, and walks its `Resources(ctx)` list.
2. Calls `.Metadata()` on each registered resource to get its real TF type name (`tsb_workspace`, `tsb_gateway_group`, ...) — this covers generated *and* hand-written resources (e.g. `access_binding`) identically, since both are registered through the same `Resources()` call.
3. Converts each TF type name to a PascalCase Pulumi type name (`gateway_group` → `GatewayGroup`, `istio_gateway_virtual_service` → `IstioGatewayVirtualService`).
4. Emits `provider/resources_gen.go`: only a `var generatedResources = map[string]*tfbridge.ResourceInfo{...}` map, alphabetically sorted, headed with `// Code generated by gen-resources-tsb. DO NOT EDIT.` — mirroring `terraform-provider-tsb`'s own `provider_gen.go` convention.

`provider/resources.go` stays hand-maintained (`Provider()`, `getProvider()` — note: `provider.New()` returns `func() provider.Provider`, a constructor, unlike checkmate's `pkg.NewProvider()` which returns a value directly, so `getProvider()` must call `provider.New()()` — token helpers, `JavaScript` package info) and references `generatedResources` for the `Resources:` field, leaving room for a future manual override (rename/deprecate a token) without fighting codegen.

**Makefile**: add a `generate` target (`go run ./provider/cmd/gen-resources-tsb -o provider/resources_gen.go`) that runs before `schema`. Add generated-file drift checking to `make check` (fails if `make generate` produces an uncommitted diff), mirroring tsb's own `make check`.

**Ongoing workflow**: bump `terraform-provider-tsb` in `go.mod`/`Makefile` → `make generate` → review the diff → `make build`.

## File layout

```
pulumi-tsb/
├── Makefile
├── go.mod / go.sum
├── index.ts, package.json(.tpl), tsconfig.json, install-pulumi-plugin.js
├── header.txt
├── provider/
│   ├── resources.go          # hand-maintained
│   ├── resources_gen.go      # generated, DO NOT EDIT
│   └── cmd/
│       ├── gen-resources-tsb/main.go
│       ├── pulumi-tfgen-tsb/main.go
│       └── pulumi-resource-tsb/main.go
├── .github/workflows/{go,release}.yml   # + SSH-agent/GOPRIVATE steps
├── .goreleaser.yml
└── README.md
```

## Validation

1. `git clone git@github.com:tetratelabs/pulumi-tsb.git ~/src/pulumi-tsb`, new working branch.
2. Overwrite root files per the layout above.
3. Write the three `provider/cmd/*` programs and `provider/resources.go`.
4. `make generate` → hand-review the resulting 48-entry `resources_gen.go`.
5. `make build` (schema → bridge → sdk) — confirms the whole pipeline actually produces a valid Pulumi schema and TypeScript SDK, not just that the Go code compiles.
6. Leave everything committed locally on the branch; ask before pushing.

## Out of scope

- Publishing/tagging a release.
- Submodule-per-resource-prefix token layout (explicitly declined in favor of flat `index`).
- Data sources (none exist in current `terraform-provider-tsb`).
- Non-TypeScript language SDKs (checkmate only generates Node.js; matching that).

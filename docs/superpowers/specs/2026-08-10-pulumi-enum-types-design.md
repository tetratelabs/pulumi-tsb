# Design: real Pulumi enum types for `pulumi-tsb`

## Context

Every enum field in the TSB API reaches Pulumi as a bare `string`. The generated schema has **zero** enum types:

```console
$ python3 -c "import json; s=json.load(open('provider/cmd/pulumi-resource-tsb/schema.json')); \
  print(len(s['types']), sum('enum' in v for v in s['types'].values()))"
6188 0
```

A representative property, `topologyChoice` on `ApplicationApiHttpServerFailoverSettings`:

```json
{
  "type": "string",
  "description": "TopologyChoice specifies the topology preference for traffic priority. ... Possible values: NONE, CLUSTER, LOCALITY.\n"
}
```

### Where the information is, and where it is lost

`terraform-provider-tsb` does not define its own schemas. Each resource delegates to a schema function generated by `protoc-gen-terraform` in the `tetrateio/tetrate` monorepo:

```go
// terraform-provider-tsb internal/provider/cluster_resource_gen.go:38
resp.Schema = fixupSchema(v2.ClusterSchema())
```

Those generated schemas encode enum-ness three ways (`api/tsb/traffic/v2/traffic_setting.pb.terraform.go:102`):

```go
"topology_choice": schema.StringAttribute{
    CustomType:  types1.EnumType,                                     // 1. type-level marker
    Default:     stringdefault.StaticString(v2.FailoverSettings_TopologyChoice_name[0]),
    Description: "... Possible values: NONE, CLUSTER, LOCALITY.",     // 2. doc-level marker
    Optional:    true,
    Validators:  []validator.String{stringvalidator.OneOf("NONE", "CLUSTER", "LOCALITY")},  // 3. validation
},
```

`EnumType` is a decorator over `basetypes.StringType` carrying no behaviour
(`api/protoc-plugins/protoc-gen-terraform/pkg/types/basetypes/enum_type.go`):

```go
type EnumType struct{ basetypes.StringType }

func (e EnumType) Equal(o attr.Type) bool {  // an enum == a plain string
    _, isEnum := o.(EnumType); _, isString := o.(basetypes.StringType)
    return isEnum || isString
}
```

The bridge erases all of it. `pkg/pf/internal/schemashim/convert_type.go:31` dispatches on the **wire**
type, and `EnumType` embeds `StringType`, so `TerraformType()` yields `tftypes.String`:

```go
tftype := typ.TerraformType(context.Background())
...
case is(tftypes.String): return shim.TypeString, nil
```

`Validators` never enter the shim at all — the whole `schemashim` package has no non-test reference to
them. Both markers are structurally invisible downstream. Only the `Description` text survives, because
descriptions are structural.

### Scale

Static scan of `api/**/*.pb.terraform.go` at `github.com/tetrateio/tetrate@v0.0.0-20260807140910-c9291b4eab25`:

| Measure | Count |
| --- | --- |
| Enum attribute sites (`CustomType: EnumType`) | 646 |
| Repeated-enum sites (`ElementType: EnumType`) | 13 |
| `stringvalidator.OneOf` validators | 656 |
| **Distinct proto enums** (import aliases resolved) | **77** |
| Distinct value sets | 65 |
| Leaf-name collisions across proto packages | 10 |

Reuse is heavy and lopsided: the value set `DISABLED, SIMPLE, MUTUAL, ISTIO_MUTUAL` alone covers 92 sites.

These are **upper bounds**. The scan covers every generated file, including `protoc-gen-terraform`'s own
test fixtures; the implementation walks only the 48 registered resources, so unreachable packages drop out.

### Why naming cannot be derived from the leaf name

`tsb/profile/v2.TLSMode` and `tsb/auth/v2.TLSMode` are different enums with **different value sets**:

| Enum | Values |
| --- | --- |
| `tsb/auth/v2.TLSMode` | `DISABLED, SIMPLE, MUTUAL, ISTIO_MUTUAL` |
| `tsb/profile/v2.TLSMode` | `DISABLED, SIMPLE, MUTUAL` |

Naming by leaf name would silently merge two enums with different allowed values — a correctness bug, not
an aesthetic one. Nine of the ten collisions involve `tsb/profile/v2`, which redeclares its own variants of
traffic/auth enums.

## Goals

- Generated Pulumi SDKs expose real enum types for TSB API enums, with IDE completion and compile-time
  checking.
- Enum identity is exact: two distinct proto enums never merge, regardless of value-set overlap.
- The mapping is regenerated mechanically on every provider bump, never hand-maintained.
- No silent degradation: anything the generator cannot resolve fails the build.

## Non-goals

- Data sources (the provider exposes none).
- Language SDKs beyond nodejs (only `sdk.nodejs` is generated today).
- Enum-member documentation. Runtime descriptors do not retain proto comments, and the attribute
  description already carries a `Possible values:` list.

## Decisions

1. **Strict enums, not relaxed.** Emit `SchemaInfo.Type` only, not `AltTypes`. Input properties narrow to
   the enum type, so existing string literals stop type-checking. This is a breaking SDK change, taken
   deliberately at `0.1.x` while it is cheap. See "Accepted consequences" for the version-skew caveat.
2. **Fix the root cause upstream** rather than reconstructing erased data. `EnumType` gains the proto
   identity it was created to carry. Rejected alternatives: value-set matching against
   `protoregistry.GlobalFiles` (ambiguous — 65 value sets for 77 enums, and it would merge the two
   `TLSMode`s), and static analysis of upstream source with `go/packages` (exact but requires a second AST
   traversal that must stay in agreement with the runtime walk).
3. **One spec, two phases.** The upstream change has no standalone value; splitting the spec would strand
   its motivation in another repo.
4. **Module per proto package.** Collisions resolve through the Pulumi module namespace rather than name
   mangling, and adding an enum later never renames an existing one.
5. **Descriptors are the sole source of member names.** No parsing of validator diagnostics or description
   text anywhere in the pipeline.
6. **Fail loudly.** A silent drop is indistinguishable from success, so every unresolved condition is a
   build error.
7. **Nothing is pushed automatically.** Work happens on a branch; commits are signed; pushing is confirmed
   with the user first (single `origin`, no fork ambiguity).

## Architecture

```
protoc-gen-terraform            terraform-provider-tsb        pulumi-tsb
─────────────────────           ──────────────────────        ──────────
proto EnumDescriptor
  │ FullName ────────┐
  ▼                  │
EnumTypeFor(         │          resp.Schema =                 gen-resources-tsb
  "…v2.TLSMode")     └────────► fixupSchema(                    walks fwschema
                                  v2.ClusterSchema())           reads .FullName
   (pure pass-through — provider repo needs only a go.mod bump)      │
                                                                     ▼
                                                         ExtraTypes + SchemaInfo tree
```

Two properties make this work:

- `gen-resources-tsb` constructs the real provider, so it holds the live `fwschema.Schema` with
  `CustomType` intact — unlike the bridge, which only ever sees the post-`tftypes` projection.
- `EnumType.Equal()` already ignores receiver contents by design, so adding a field is behaviour-preserving
  for every existing consumer.

## Phase 1 — `tetrateio/tetrate`

Four edits in `api/protoc-plugins/protoc-gen-terraform`, plus a regeneration.

**1. `pkg/types/basetypes/enum_type.go`** — carry the identity:

```go
type EnumType struct {
    basetypes.StringType
    FullName protoreflect.FullName // e.g. "tetrateio.api.tsb.auth.v2.TLSMode"
}
```

`String()` becomes `"prototypes.EnumType(" + FullName + ")"` so schema dumps stay informative. `Equal()` is
unchanged — deliberately still contents-blind.

**2. `pkg/types/enum.go`** — add a constructor, retaining the bare `EnumType` var so any hand-written
consumer keeps compiling:

```go
func EnumTypeFor(name protoreflect.FullName) basetypes.EnumType {
    return basetypes.EnumType{FullName: name}
}
```

**3. `pkg/generate/enum.go:70`** — the singular path. `enumDescriptor(f)` already exists and resolves
singular, list and map-valued enums uniformly:

```go
d[j.Id("CustomType")] = j.Qual(ProtoTypes, "EnumTypeFor").
    Call(j.Lit(string(enumDescriptor(f).FullName())))
```

**4. `pkg/generate/schema.go:205`** — the element-type path. `protoreflect.EnumKind` currently sits in
`primitiveSchemaTypeMap`, a package-level `map[protoreflect.Kind]*j.Statement` with no field context, so
enums must graduate out of that table into a field-aware branch at the lookup site. This also removes a
latent hazard: those `*j.Statement` values are mutable and shared across every call site.

**5. Regenerate** `api/**/*.pb.terraform.go` — 96 files, purely mechanical.

`terraform-provider-tsb` has **zero** direct references to `EnumType`, so no coordinated change is needed
there beyond a dependency bump.

## Phase 2 — `pulumi-tsb`

### Generator

`gen-resources-tsb` currently calls `r.Metadata(...)` per resource
(`provider/cmd/gen-resources-tsb/main.go:34`). It gains a second call, `r.Schema(...)`, and a recursive
walk producing two outputs:

```
walk(resource.Schema) ──┬─► sites: []{resourceType, []pathStep, protoFullName}
                        └─► enums: set[protoFullName]

for each FullName:
    protoregistry.GlobalFiles.FindDescriptorByName(fn) → EnumDescriptor → Values()
```

Every API package is linked into the generator binary via `tsbprovider`, so `GlobalFiles` is complete.

Detection is a typed assertion — `EnumType.Equal()` is contents-blind and would match plain strings:

```go
if et, ok := attr.GetType().(prototypes.EnumType); ok { /* et.FullName */ }
```

`github.com/tetrateio/tetrate/api/protoc-plugins/protoc-gen-terraform/pkg/types` is a public path (not
`internal`), so it becomes a direct dependency of `pulumi-tsb`.

Node kinds the walk handles: root `Attributes`; `SingleNestedAttribute.Attributes`;
`{List,Set,Map}NestedAttribute.NestedObject.Attributes`; `{List,Set,Map}Attribute.ElementType`;
`ObjectAttribute.AttributeTypes`.

### Path → `SchemaInfo` addressing

Verified against `pkg/tfgen/generate.go:519` (single-nested) and `:541` (list-nested), which both descend
with `elemInfo = info.Elem`; the bridge's own test uses `Fields["rules"].Elem.Fields["action_parameters"]`.
Uniform rule, one `.Elem` per nesting level:

| Framework node | Emitted |
| --- | --- |
| `StringAttribute` (enum) | `{Type: tok}` |
| `SingleNestedAttribute` | `{Elem: &SchemaInfo{Fields: {…}}}` |
| `{List,Set,Map}NestedAttribute` | `{Elem: &SchemaInfo{Fields: {…}}}` |
| `{List,Map}Attribute` with enum `ElementType` | `{Elem: &SchemaInfo{Type: tok}}` |

Only paths leading to an enum leaf are emitted, so `resources_gen.go` stays proportional to enum sites
rather than to the whole schema. Illustrative shape (path and token not verified against a real resource):

```go
"tsb_gateway_tier1_gateway": {Tok: ..., Fields: map[string]*tfbridge.SchemaInfo{
    "spec": {Elem: &tfbridge.SchemaInfo{Fields: map[string]*tfbridge.SchemaInfo{
        "http": {Elem: &tfbridge.SchemaInfo{Fields: map[string]*tfbridge.SchemaInfo{
            "tls": {Elem: &tfbridge.SchemaInfo{Fields: map[string]*tfbridge.SchemaInfo{
                "mode": {Type: "tsb:auth/TLSMode:TLSMode"},
            }}},
        }}},
    }}},
}},
```

### Enum type definitions

One `ProviderInfo.ExtraTypes` entry per reachable enum, injected verbatim into the schema
(`pkg/tfgen/generate_schema.go:453`):

```go
"tsb:auth/TLSMode:TLSMode": pschema.ComplexTypeSpec{
    ObjectTypeSpec: pschema.ObjectTypeSpec{Type: "string"},
    Enum: []pschema.EnumValueSpec{
        {Name: "Disabled",    Value: "DISABLED"},
        {Name: "Simple",      Value: "SIMPLE"},
        {Name: "Mutual",      Value: "MUTUAL"},
        {Name: "IstioMutual", Value: "ISTIO_MUTUAL"},
    },
},
```

`JavaScriptInfo.ContainsEnums = true` is set on `ProviderInfo`.

`ExtraTypes` is currently unused by this provider; `resources.go` gains the field alongside `Resources`,
populated from a new `generatedEnums` var in `resources_gen.go`.

### Naming

**Module** — derived from the proto package, camel-cased between the `tsb.`/`install.` segment and the
version segment:

```
tetrateio.api.tsb.v2                         → index
tetrateio.api.tsb.auth.v2                    → auth
tetrateio.api.tsb.observability.telemetry.v2 → observabilityTelemetry
tetrateio.api.install.controlplane.v1alpha1  → installControlplane
```

Most land on modules that already exist for resources (`gateway`, `traffic`, `security`, `profile`,
`application`, `extension`).

A package outside `tetrateio.api` (the scan found one reference to `google.protobuf.Syntax`) has no
derivable module and is a generation error unless it has an explicit remap entry. This is deliberate: such
enums are rare, and guessing a namespace for them is worse than being told about them.

**Type name** — the proto message path within the package, joined and PascalCased, mirroring the Go symbol
the descriptor already produces. The leaf name alone is insufficient: two messages in one package may each
nest an enum of the same name.

```
tetrateio.api.tsb.auth.v2.TLSMode                       → tsb:auth/TLSMode:TLSMode
tetrateio.api.tsb.gateway.v2.ServerTLSSettings.TLSMode  → tsb:gateway/ServerTLSSettingsTLSMode:…
tetrateio.api.tsb.traffic.v2.FailoverSettings.TopologyChoice
                                                        → tsb:traffic/FailoverSettingsTopologyChoice:…
```

Existing initialisms in the proto identifiers (`TLS`, `OIDC`, `AWS`) are preserved as written rather than
re-cased. Two enums deriving the same token within a module is a generation error.

**Reserved module names.** The nodejs SDK already generates `sdk/types/`, `sdk/config/` and `sdk/scripts/`,
so a module with any of those names would clash — and `tsb/types/v2` is the third-largest enum package
(~70 sites). `private` is additionally a TypeScript keyword. An explicit remap table handles the known
cases (`types → coretypes`), and generation **fails** if a derived module name hits the reserved set
without a remap entry, so a future upstream package cannot silently produce a broken SDK.

**Members** — `SCREAMING_SNAKE` → PascalCase (`ISTIO_MUTUAL` → `IstioMutual`, `TLSV1_0` → `Tlsv10`), with
post-mangling collision detection failing generation. Supplying an explicit `Name` on each
`EnumValueSpec` keeps the committed output deterministic and reviewable rather than dependent on
per-language derivation.

## Failure handling

A silent drop looks exactly like success, so every unexpected condition fails the build rather than
emitting fewer enums:

- `EnumType` whose `FullName` is absent from `protoregistry.GlobalFiles` → error.
- `FindDescriptorByName` returning a non-enum descriptor → error.
- Derived module name in the reserved set with no remap entry → error.
- Enum outside `tetrateio.api` with no remap entry → error.
- Two enums deriving the same type token within a module → error.
- Member-name collision after PascalCase mangling → error.
- Schema node kind the walk does not recognise (e.g. `Blocks`, unused by these schemas today) → error, not
  skip.

## Verification

1. **Existing drift guard extends for free.** `make check` runs `generate` and fails on a dirty tree, so a
   stale `resources_gen.go` is already caught.
2. **Post-generation invariant.** After `make schema`, assert that the number of enum `$ref`s in
   `schema.json` equals the site count the walk found, and that `len(types)` grew by exactly the reachable
   enum count. This is the load-bearing check: it is what catches a `Fields`/`Elem` tree that silently
   fails to match. Counts are derived from the walk, never hardcoded.
3. **SDK typecheck.** A `tsc --noEmit` step over the generated `sdk/`, so strict enums that break
   compilation surface in CI rather than in a user's editor.
4. **Unit tests** for the pure functions — module derivation, member mangling, and path→`SchemaInfo` tree
   construction — table-driven, no provider needed.

## Release chain

Three sequential steps, all on existing rails:

| # | Repo | Change |
| --- | --- | --- |
| 1 | `tetrateio/tetrate` | Phase 1 → merge → new pseudo-version |
| 2 | `tetratelabs/terraform-provider-tsb` | `go.mod` bump of `github.com/tetrateio/tetrate` → tag |
| 3 | `tetratelabs/pulumi-tsb` | `PROVIDER_VERSION` bump + Phase 2 |

Step 2 is a pure dependency bump: the schema functions' signatures do not change, only their contents, and
`fixupSchema` inspects `Default`s rather than types. Step 3 follows the existing `bump-terraform-provider`
workflow.

## Accepted consequences

- **Breaking SDK change.** String literals stop type-checking on enum properties. Taken deliberately at
  `0.1.x`.
- **Outputs narrow too.** Every enum attribute is `Optional+Computed` (upstream's `fixupSchema`), so it
  appears as both an input and an output. A server newer than the compiled descriptors returns a value
  protobuf-go renders as a decimal string (e.g. `"7"`), which upstream deliberately preserves rather than
  rejects (`terraform-provider-tsb internal/provider/conv.go:53`). Such a value is outside the declared
  enum type. TypeScript enums erase to strings at runtime, so this is a type-level inaccuracy rather than a
  crash. To be noted in the SDK README.
- **Release coupling.** `pulumi-tsb` cannot ship this until Phases 1 and 2 of the release chain land.

# GitHub Packages Publishing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `@tetratelabs/pulumi-tsb` to GitHub Packages on tag push, and make the published tarball installable and importable.

**Architecture:** The release workflow's `npmpublish` job switches registry to `https://npm.pkg.github.com` and authenticates with the workflow's built-in `GITHUB_TOKEN`. Three pre-existing packaging defects are fixed first — a broken runtime `package.json` lookup, a missing `main` field, and a missing `files` allowlist — each gated by a new `hack/smoke-package.sh` that packs the tarball, installs it into a scratch project, and imports it.

**Tech Stack:** GitHub Actions, npm (Node 20), TypeScript, GNU Make, Bash.

Spec: `docs/superpowers/specs/2026-07-27-github-packages-publishing-design.md`

## Global Constraints

- Package name stays `@tetratelabs/pulumi-tsb`; the scope must match the `tetratelabs` org for GitHub Packages to accept it.
- Registry is `https://npm.pkg.github.com`. Do not add an npmjs publish target.
- Authentication uses `secrets.GITHUB_TOKEN`. Do not introduce a new secret.
- `package.json` is generated from `package.json.tpl` by `make sdk.nodejs`, and `sdk/utilities.ts` is generated by `make sdk`. Any change to a generated file MUST also be made to its generator, or the next `make` run reverts it.
- Commits are signed and signed-off: `git commit -S -s`. No `Co-Authored-By` or AI attribution trailers.
- Work happens on the existing branch `github-packages-publishing`. Do not commit to `main`.
- Do not run `make sdk` / `make generate`. Those need the private Go toolchain and network access, and would produce large unrelated diffs. Edit generated files and their generators in tandem instead.

## Task 1: Add the packaging smoke test

Creates the failing test that gates Tasks 2 and 3. It is expected to FAIL at the end of this task — that is the point. Nothing in CI runs it yet, so no pipeline turns red.

**Files:**
- Create: `hack/smoke-package.sh`

**Interfaces:**
- Consumes: nothing.
- Produces: `hack/smoke-package.sh`, an executable taking no arguments, exiting 0 on success and non-zero with a `FAIL:` line on failure. Task 4 invokes it as `./hack/smoke-package.sh` from the repo root.

- [ ] **Step 1: Write the failing test**

Create `hack/smoke-package.sh`:

```bash
#!/usr/bin/env bash
# Verifies that the tarball `npm publish` would upload is installable and
# importable. Run from anywhere; it operates on the repo root.
set -euo pipefail

cd "$(dirname "$0")/.."
ROOT="$PWD"

PKG_VERSION="$(node -p "require('./package.json').version")"
TARBALL="$ROOT/tetratelabs-pulumi-tsb-${PKG_VERSION}.tgz"
SMOKE_DIR="$(mktemp -d)"

cleanup() { rm -rf "$SMOKE_DIR" "$TARBALL"; }
trap cleanup EXIT

# `npm pack` runs the `prepare` script, which populates dist/ via tsc.
# dist/ still will not reach the tarball until `files` is set: without an
# allowlist npm falls back to .gitignore, which excludes dist/.
npm pack --silent >/dev/null
if [ ! -f "$TARBALL" ]; then
  echo "FAIL: expected tarball at $TARBALL"
  exit 1
fi

# Capture the listing once rather than piping `tar` into `grep -q` per check.
# Under `set -o pipefail` that pipeline is unsound: `grep -q` exits at the
# first match, `tar` then takes SIGPIPE and returns 141, and the pipeline
# reports failure even though the pattern matched. For the negative check
# below that would mean a silent pass.
CONTENTS="$(tar -tzf "$TARBALL")"

echo "--- tarball contents ---"
echo "$CONTENTS"
echo "-----------------------"

if ! grep -q '^package/dist/index\.js$' <<<"$CONTENTS"; then
  echo "FAIL: dist/index.js missing from tarball"
  exit 1
fi
if ! grep -q '^package/sdk/scripts/install-pulumi-plugin\.js$' <<<"$CONTENTS"; then
  echo "FAIL: sdk/scripts/install-pulumi-plugin.js missing from tarball"
  exit 1
fi
if grep -q '^package/provider/' <<<"$CONTENTS"; then
  echo "FAIL: Go provider sources leaked into the tarball"
  exit 1
fi

cd "$SMOKE_DIR"
npm init -y >/dev/null
# --ignore-scripts skips the `install` hook, which downloads the provider
# binary from the GitHub Release for this tag. That release may not exist yet
# and is not what this test covers.
npm install --ignore-scripts --no-audit --no-fund "$TARBALL" >/dev/null

node -e '
  const pkg = require("@tetratelabs/pulumi-tsb");
  if (typeof pkg.Cluster === "undefined") {
    throw new Error("expected Cluster export to be present");
  }
  const { getVersion } = require("@tetratelabs/pulumi-tsb/dist/sdk/utilities");
  const got = getVersion();
  const want = require("@tetratelabs/pulumi-tsb/package.json").version;
  if (got !== want) {
    throw new Error("getVersion() returned " + got + ", want " + want);
  }
  console.log("OK: imported package, getVersion() = " + got);
'
```

- [ ] **Step 2: Make it executable**

```bash
chmod +x hack/smoke-package.sh
```

- [ ] **Step 3: Run it to verify it fails**

Run: `./hack/smoke-package.sh`

Expected: FAIL with `FAIL: dist/index.js missing from tarball`.

The cause is worth understanding, because it is the first of the three defects to surface: with no `files` allowlist, npm falls back to `.gitignore` when deciding what to pack, and `.gitignore` lists `dist/`. So `prepare` compiles `dist/` and npm then omits it. Task 3 adds the allowlist, which overrides `.gitignore`.

Do NOT fix anything here.

- [ ] **Step 4: Commit**

```bash
git add hack/smoke-package.sh
git commit -S -s -m "Add packaging smoke test for the published tarball"
```

## Task 2: Fix the runtime package.json lookup

`sdk/utilities.ts` does `require('../package.json')`. It executes from `dist/sdk/`, so that path resolves to `dist/package.json`, which does not exist. `getVersion()` throws, and because `dist/sdk/index.js` calls into utilities at load time, importing the package fails outright.

**Files:**
- Modify: `Makefile` (the `sdk.nodejs` target)
- Modify: `sdk/utilities.ts:47`

**Interfaces:**
- Consumes: `hack/smoke-package.sh` from Task 1.
- Produces: `getVersion()` in `dist/sdk/utilities.js` returns the root `package.json` version as a string. Task 3's smoke run depends on this.

- [ ] **Step 1: Run the narrow failing test**

Run:

```bash
npm run build && node -e "require('./dist/index.js')"
```

Expected: FAIL with `Error: Cannot find module '../package.json'` and a require stack naming `dist/sdk/utilities.js`.

- [ ] **Step 2: Fix the generator**

In `Makefile`, inside the `sdk.nodejs` target, replace this line:

```make
	sed -i -e 's/.\/package.json/..\/package.json/' sdk/utilities.ts
```

with:

```make
	sed -i -e "s|require('\./package\.json')|require('../../package.json')|" sdk/utilities.ts
	grep -q "require('../../package.json')" sdk/utilities.ts || (echo utilities.ts package.json path rewrite failed && false)
```

Two changes: the replacement now climbs two levels (from `dist/sdk/` to the package root), and the pattern is anchored on the full `require(...)` call so a change in the generator's output fails the grep guard instead of silently producing a broken SDK. The guard follows the same style as the existing `providerversion` and `versioncheck` targets.

- [ ] **Step 3: Apply the same change to the generated file**

`sdk/utilities.ts` is committed and is not being regenerated in this plan, so hand-apply the rewrite. Change line 47 from:

```typescript
    let version = require('../package.json').version;
```

to:

```typescript
    let version = require('../../package.json').version;
```

- [ ] **Step 4: Rebuild and verify the test passes**

Run:

```bash
npm run build && node -e "require('./dist/index.js'); console.log('import OK')"
```

Expected: PASS, printing `import OK`.

- [ ] **Step 5: Verify getVersion resolves**

Run:

```bash
node -e "console.log(require('./dist/sdk/utilities').getVersion())"
```

Expected: prints `0.1.1` (whatever `package.json` currently declares), not an error.

- [ ] **Step 6: Commit**

```bash
git add Makefile sdk/utilities.ts
git commit -S -s -m "Fix package.json path in compiled SDK utilities"
```

## Task 3: Fix package metadata for publishing

Adds `main` so the package can be required by name, `files` so the Go provider tree stays out of the tarball, `repository` so GitHub links the package to the repo, and `publishConfig` so a manual `npm publish` targets the right registry.

**Files:**
- Modify: `package.json.tpl`
- Modify: `package.json`

**Interfaces:**
- Consumes: `hack/smoke-package.sh` from Task 1; the working `getVersion()` from Task 2.
- Produces: a tarball containing exactly `dist/`, `sdk/scripts/`, `package.json`, and `README.md`. Task 4 publishes it.

- [ ] **Step 1: Run the failing test**

Run: `./hack/smoke-package.sh`

Expected: FAIL with `FAIL: dist/index.js missing from tarball`. Task 2 fixed the runtime `require` path but not what npm packs, so the tarball is still filtered by `.gitignore` — which excludes `dist/`. The `files` allowlist added in Step 2 is what overrides that.

- [ ] **Step 2: Update the template**

Replace the full contents of `package.json.tpl` with:

```json
{
  "name": "@tetratelabs/pulumi-tsb",
  "version": "${VERSION}",
  "description": ". Based on terraform-provider-tsb: version v${PROVIDER_VERSION}",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "repository": {
    "type": "git",
    "url": "git+https://github.com/tetratelabs/pulumi-tsb.git"
  },
  "publishConfig": {
    "registry": "https://npm.pkg.github.com"
  },
  "files": [
    "dist/",
    "sdk/scripts/"
  ],
  "scripts": {
    "build": "tsc",
    "prepare": "npm run build",
    "install": "node sdk/scripts/install-pulumi-plugin.js resource tsb ${VERSION} --server github://api.github.com/tetratelabs"
  },
  "dependencies": {
    "@pulumi/pulumi": "^3.0.0"
  },
  "devDependencies": {
    "@types/node": "^10.0.0",
    "typescript": "^4.3.5"
  },
  "pulumi": {
    "resource": true,
    "name": "tsb"
  }
}
```

`sdk/scripts/` must stay in `files` because the `install` lifecycle script runs `node sdk/scripts/install-pulumi-plugin.js` on the consumer's machine. npm always includes `package.json`, `README.md`, and `LICENSE` regardless of the allowlist.

- [ ] **Step 3: Apply the same change to the generated file**

`package.json` is generated from the template by `make sdk.nodejs`, which is not being run here. Hand-apply the identical change to `package.json`, substituting `${VERSION}` with `0.1.1` and `${PROVIDER_VERSION}` with the value already present in the file's `description`. Do not change `version` or `description`.

The result must be byte-identical to what `sed -e 's/${VERSION}/0.1.1/g' -e 's/${PROVIDER_VERSION}/<current>/g' package.json.tpl` would produce.

Expected: prints `in sync` with no diff output. If `PROVIDER_VERSION` in the `Makefile` has moved on, use that value instead.

Expected: succeeds. `package-lock.json` may or may not change — `main` and `files` are not mirrored in the lock, so an unchanged file is a valid outcome.

Expected: PASS. The tarball listing shows only `package/package.json`, `package/README.md`, `package/dist/...`, and `package/sdk/scripts/install-pulumi-plugin.js`, followed by `OK: imported package, getVersion() = 0.1.1`.

## Task 4: Publish to GitHub Packages

**Files:**
- Modify: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: `hack/smoke-package.sh` from Task 1.
- Produces: a release workflow that publishes to GitHub Packages after `goreleaser` succeeds.

- [ ] **Step 1: Move permissions from workflow level to job level**

In `.github/workflows/release.yml`, delete these two lines that sit between `on:` and `jobs:`:

```yaml
permissions:
  contents: write
```

Then add a `permissions` block to the `goreleaser` job, directly under `runs-on: ubuntu-latest`:

```yaml
  goreleaser:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
```

`goreleaser` still needs `contents: write` to create the release. Moving the block lets `npmpublish` request a different scope.

- [ ] **Step 2: Replace the npmpublish job**

Replace the entire `npmpublish` job — from `  npmpublish:` to the end of the file — with:

```yaml
  npmpublish:
    needs: goreleaser
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4
      - run: make tagcheck
      - uses: actions/setup-node@v4
        with:
          node-version: '20.x'
          registry-url: 'https://npm.pkg.github.com'
          scope: '@tetratelabs'
      - run: npm ci
      - name: Verify the tarball is installable
        run: ./hack/smoke-package.sh
      - run: npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Four substantive changes from the previous job: `needs: goreleaser` closes the window where the package exists but its provider binary does not; the registry and scope point at GitHub Packages; `NODE_AUTH_TOKEN` comes from the built-in `GITHUB_TOKEN` instead of `secrets.NPM_TOKEN`; and `npm publish` runs at the repo root rather than `cd dist`, where no `package.json` exists.

- [ ] **Step 3: Verify the workflow parses and asserts hold**

Run:

The workflow contains `${{ ... }}`, which a double-quoted shell string would try
to expand, so this script is single-quoted and uses plain substring checks:

```bash
node -e '
  const s = require("fs").readFileSync(".github/workflows/release.yml", "utf8");
  const must = [
    "registry-url: \x27https://npm.pkg.github.com\x27",
    "scope: \x27@tetratelabs\x27",
    "needs: goreleaser",
    "packages: write",
    "secrets.GITHUB_TOKEN",
    "./hack/smoke-package.sh",
  ];
  const mustNot = ["NPM_TOKEN", "cd dist && npm publish", "registry.npmjs.org"];
  for (const m of must) {
    if (!s.includes(m)) throw new Error("missing: " + m);
  }
  for (const m of mustNot) {
    if (s.includes(m)) throw new Error("still present: " + m);
  }
  console.log("release.yml assertions OK");
'
```

Expected: prints `release.yml assertions OK`.

- [ ] **Step 4: Verify the YAML is well-formed**

Run:

```bash
python3 -c "import yaml,sys; d=yaml.safe_load(open('.github/workflows/release.yml')); print(sorted(d['jobs'])); print(d['jobs']['npmpublish']['permissions'])"
```

Expected:

```

{'contents': 'read', 'packages': 'write'}
```

**Files:**

**Interfaces:**

- [ ] **Step 1: Add an Installing section**

In `README.md`, insert this section after the "Generated from the tsb terraform provider" line and before `## Updating`:

````markdown
## Installing

The package is published to GitHub Packages, which requires authentication for
reads even though this repository is public. Add an `.npmrc` next to your
`package.json`:

```
@tetratelabs:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

Set `GITHUB_TOKEN` to a personal access token with the `read:packages` scope,
then:

```
npm install @tetratelabs/pulumi-tsb
```

Installing runs `pulumi plugin install`, which downloads the provider binary
from this repository's GitHub Releases. That download is unauthenticated — the
token is only needed for the npm package itself.
````

Run `make tagcheck` first to check that the tag matches the provider version,
